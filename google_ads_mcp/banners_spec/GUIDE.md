# Как верстать баннер для Google Ads App-кампаний

Читать перед тем, как писать вёрстку. Отдаётся инструментом `banner_spec`.

## Что пишешь ты, а что код

Ты пишешь **только содержимое сцены**: `body_html`, `css`, `js`.

Всё остальное собирает `build_banner` и сломать это нельзя: `<!DOCTYPE>`, `<head>`,
мета-теги `ad.size` и `ad.orientation`, литеральный тег `exitapi.js`, CSS-reset,
контейнеры `#bleed` / `#stage`, движок резиновости `fit.js`, функция `adExit()`.

Не пиши сам: `<html>`, `<head>`, `<body>`, `<style>`, `<script src=...>`, DOCTYPE.

## Разметка сцены

```
#bleed   — фикс. слой на весь экран, z-index 0. Сюда фон: градиент, картинка.
#stage   — сцена 320x480 (или 480x320), z-index 1. Сюда весь контент.
```

Верстай в **фиксированной пиксельной сетке** 320×480. Не думай про адаптив —
`fit.js` отмасштабирует сцену под реальный слот по ширине и растянет высоту
в пределах `dh_min..dh_max` (по умолчанию 400–720).

Из этого следует: **фон всегда на `#bleed`**, иначе по краям вылезут полосы,
когда слот выше сцены. Контент — на `#stage`.

## Клик

CTA вешается на `onclick="adExit()"`. Функция уже определена, сама разбирается
с `ExitApi`.

Не изобретай `clickTag` — в Google Ads такого нет вообще, это конвенция CM360/DV360.

Один exit на баннер. Несколько — проверка `Multiple Click Exits` даст FAIL.

## Жёсткие запреты

Завалят модерацию, проверяются автоматически:

- `<iframe>`, `<frame>`, `<audio>`, AMP-теги
- `localStorage`, `sessionStorage`, `document.cookie` — креатив в sandbox
  без `allow-same-origin`, будет SecurityError
- `document.write`
- любые внешние URL кроме Google Fonts / Google-hosted jQuery / GSAP / `tpc.googlesyndication.com`
- самозакрывающиеся SVG-теги: `<path/>` невалиден, писать `<path></path>`
- файлы вне белого списка: только `.css .gif .html .jpeg .js .png .svg`
  (`.jpg` формально отсутствует, шрифтовых расширений нет вообще)

## Шрифты

Системный стек работает всегда:
`-apple-system, "Segoe UI", Roboto, Arial, sans-serif`

Google Fonts подключать можно (единственный разрешённый внешний источник), но
это сетевой запрос в рантайме — если слот его не дождётся, увидишь фолбэк.
Для фирменного шрифта надёжнее отрендерить заголовок в прозрачный PNG
инструментом `banner_render_text` и положить картинкой.

## Что реально ломается

**Пустой баннер.** Ворота рендера ловят его по числу цветов в кадре. Причина
почти всегда одна: контент лежит вне `#stage` или уехал за `overflow:hidden`.

**Переполнение по высоте.** Длинный заголовок на CJK или немецком вылезает за
сцену. Считай запас: 320px ширины — это ~18 символов в 34px. Для японского
и арабского бери кегль на ступень мельче.

**Анимация.** CSS-анимации разрешены. Держи цикл в пределах 30 секунд,
не гоняй бесконечно тяжёлые трансформы — слот может быть на слабом устройстве.
`prefers-reduced-motion` уважать не обязательно, но и не вредно.

## Два рабочих паттерна

**`css`** — без растра, стоит ноль. Системные алерты, уведомления, типографика,
UI-мокапы, геометрия, градиенты, инлайновый SVG. Сюда же попадает большинство
форматов вида «псевдосистемное сообщение».

**`art`** — с растровой картинкой от `banner_generate_art`. Эмоциональные
креативы: персонаж, сцена, предметная съёмка. Картинка идёт на `#bleed`
как `background-image`, поверх — тёмный скрим градиентом, чтобы текст читался:

```css
#bleed{background:url(art.jpeg) center/cover}
#scrim{position:absolute;inset:0;
  background:linear-gradient(0deg,rgba(0,0,0,.78),transparent 60%)}
```

Скрим в CSS, а не «чистая зона» в самой картинке — зона уезжает при любом
рекропе, скрим не уезжает никогда.

## Проверка

`build_banner` при `strict=True` не отдаст путь к ZIP, если есть FAIL —
вернёт список «правило / что не так / как чинить». Чини и пересобирай.

WARN не блокирует, но читать стоит.

Проверка `google:Ad Dimensions` для App-кампаний понижена до INFO: валидатор
гоняет размер по Display-списку, где 320×480 отсутствует, хотя для App это
как раз правильный размер и Ads API такой бандл принимает.

## Промпт на арт — главная грабля

Модель понимает пространственные указания **буквально**. Любой намёк на зоны
внутри кадра превращается в реальные полосы с резкой границей:

- ❌ `empty safe space at top and bottom for text`
- ❌ `upper and lower thirds low-detail gradient` ← проверено, даёт леттербокс
- ❌ `leave room for the headline`

Пиши только **что на кадре**, и требуй цельности:
`single continuous photograph filling the entire frame, no horizontal bands`
(негативы `generate_art` подставляет сам).

Место под текст делается **скримом в CSS**, а не пустотой в картинке. Скрим
переживает любой рекроп, пустая зона — нет.

`generate_art` детектит полосы по перепаду яркости и один раз переснимает
автоматически. Если в ответе есть `warning` — кадр всё равно с полосами,
переформулируй промпт.
